# Agent Workbench「自动升级 / 自我进化」设计

**状态：** 设计稿 v2（未实施）
**目标：** 用户启动一轮后，Agent 在明确授权范围内自主判断改进方向、联网调研、实施和验证；用户可随时暂停或撤回授权。
**最高权限：** 用户控制目标、授权边界、预算和正式合入；Agent 在授权范围内有独立的方向选择和执行决定权。

## 1. 产品定义

“变强”指 Agent Workbench 的代码、工具、可靠性和任务完成能力经过证据与测试验证后改善，不代表 API 调用能训练或改变底层模型参数。

用户点击「开始升级」后，Agent 不必逐步等待用户批准。它可自主完成一轮有上限的闭环：

1. 检查项目结构、现有测试、近期任务失败和已知限制，建立基线。
2. 搜索公开的官方文档、项目更新、缺陷记录和安全公告，保存可复核来源。
3. 根据用户目标和项目证据选择本轮最值得做的一项改进；记录为什么选择它、考虑过哪些替代项。
4. 在独立候选副本中实施、运行测试，并在预算内自行修正或放弃无效方案。
5. 形成候选差异、来源、测试和用量报告，停在「待你验收」。

每次启动最多完成一个改进闭环；不会无限循环、自动开始下一轮或为了消耗 Token 而找事做。若没有有证据且符合授权的改进，结束为「本轮无改动」。

## 2. 决策权与权限分层

用户设定并随时可改的授权章程是最高规则，Agent 不能修改章程、扩大自己的工具权限、提高预算或改写评估标准。每轮启动时保存一份授权快照，便于事后追溯；用户撤回授权后，Worker 不再发起新的动作。

| 层级 | Agent 的权限 | 默认处理 |
| --- | --- | --- |
| 自主执行 | 检查项目；搜索公开资料；决定改进目标和方案；在候选副本编辑；运行隔离测试；在预算内重试、放弃或收敛；记录本轮决策 | 不必等用户逐步批准 |
| 需要授权 | 引入新依赖或大版本升级；数据库迁移；新增外部服务；改变认证、网络或安全边界；访问授权范围外的仓库 | 暂停在 `waiting_owner`，说明原因和影响，等待用户授权 |
| 禁止自行执行 | 读取/展示密钥；修改授权章程、预算上限或评估基线；合并正式分支；推送公开仓库；生产部署；删除正式数据；代表用户对外发言或消费超预算 | 无论用户是否在线都不能自行越过 |

默认允许 Agent 在现有候选工作区内作出真正的工程决定并完成改动。若工作区是 Git 仓库，可使用独立本地分支（如 `autoupgrade/<run-id>`）；否则使用现有候选副本。V1 不自动 Push。正式合入仍由用户控制。

如果 Agent 碰到章程以外或风险不明确的动作，应选择安全暂停，而不是把用户暂时不在线当作默许。用户可随时暂停、放弃候选、批准边界授权或验收合入。

## 3. 用户界面

升级面板显示：

- **长期目标 / 本轮重点**：默认优先提升复杂任务的可靠交付、安全性和可恢复性；用户可调整排序或填写目标。
- **授权档位**：默认「自主做到候选结果，不合入正式版本」。明确显示允许、需批准和禁止事项。
- **预算与时限**：启动前可见 Token 上限、模型调用数、搜索次数、最长运行时间；禁止无限运行。
- **开始升级**：创建授权快照后，Agent 自主推进一轮。
- **安全暂停 / 继续升级 / 放弃本轮**：暂停保留候选与检查点；放弃需二次确认并只清理本轮候选。
- **验收报告**：展示 Agent 决策理由、选中与未选方案、来源、测试、用量、分支/候选区及完整差异；用户可通过、退回、放弃或撤销已合入改动。

阶段用中文展示：`检查项目 → 联网调研 → 选择方向 → 隔离实现 → 运行测试 → 待你验收`。触及需批准事项时显示「等待你的授权」，并指出具体原因。Token 显示为“服务商返回值 / 估算值 / 暂不可知”。

## 4. 状态与检查点

复用现有 `tasks`、`events`、候选目录和单 Worker，不另部署工作流服务。升级任务设置 `task_type='upgrade'`，普通任务行为不变。

```text
queued → running ⇄ pause_requested → paused → running
             ├→ waiting_owner ⇄ running
             ├→ review → succeeded（用户批准合入）
             ├→ no_change
             └→ failed（检查点存在时可恢复）
paused / failed / waiting_owner → running（继续或授权后恢复）
```

SQLite 增量字段建议：

- `task_type`、`phase`、`pause_requested`
- `checkpoint_json`（带 schema 版本，记录已完成阶段、模型上下文、下一动作、当前候选标识）
- `authority_snapshot_json`（本轮不可被 Agent 修改的授权快照）
- `base_fingerprint`（启动时正式工作区文件清单/内容指纹）
- `budget_limit_tokens`、`input_tokens`、`output_tokens`、`usage_quality`
- `task_sources` 保存来源标题、网址、类型、摘要、检索时间和内容哈希
- 决策记录写入事件流：选择的目标、依据、考虑过的方案、停止/收敛原因

每个阶段结束后、每次模型请求或工具调用前后保存检查点。应用重启后，升级任务从最近检查点恢复，候选文件不得因普通服务重启而丢弃。恢复前比较 `base_fingerprint`；若正式工作区已变化，则进入冲突处理，不静默覆盖。

如果服务器在模型请求发出后、保存响应前崩溃，服务商可能已计费。该次调用标记为 `unknown`；若 API 支持幂等键则使用，否则恢复时提示可能重复计费，不自动重发，须由用户选择重试或放弃该轮。

## 5. 安全暂停和撤回授权

「暂停」与现有的「取消任务」明确区分：

1. 立即持久化暂停请求；Worker 不启动新的模型、搜索或工具动作。
2. 当前模型响应返回后先保存响应和检查点，再转为 `paused`。已经发出的 API 请求可能仍会计费，暂停不能承诺退款或瞬时取消。
3. 长命令通过 `operation_id` 管理；Runner 收到暂停信号后向命令进程组发送 `SIGTERM`，宽限期后才 `SIGKILL`，清理命令临时目录但保留候选源文件。
4. 撤回授权等价于不再启动任何新动作；不合入、不推送、不部署。
5. 「放弃本轮」是显式清理本轮候选，不等同于暂停；正式工作区不受影响。

## 6. 联网搜索与工具边界

- App 侧通过专用 `web_search` 工具做只读公开搜索；Runner 继续无网络、无 API Key。
- 首选官方文档、官方仓库 Release/Issue、安全公告；保存来源以便用户复核。搜索发现只是 Agent 决策证据，不是用户授权。
- 网页内容属于不可信资料，不可覆盖系统规则或授权章程，也不能要求 Agent 读取密钥、改变权限或执行网页命令。
- 不开放任意 URL 抓取；需要读取页面时仅允许 HTTPS 公网目标，校验 DNS 和重定向，阻止 localhost、私网、云元数据地址，并设置超时及响应大小上限。
- Agent 不能读取 `.env`、SSH 密钥、数据库凭据等敏感文件；候选区和命令执行环境不挂载宿主机密钥或 Docker socket。（已知路径过滤只覆盖常见文件名和目录，不是完整的内容级秘密扫描；请勿在工作区保存其他密钥。）

## 7. 预算、目标和验证

“Agent 有决定权”不等于无限预算。预算、时限和授权由用户设定且 Agent 不可修改。服务商返回 `usage` 时记录实际输入/输出 Token；未返回时明确标记估算或未知。即使 Token 精确用量不可得，也要通过模型调用数、输出长度、搜索次数和总时限设硬上限；触顶后不发起下一步并保存状态。

默认长期目标建议为：**提高复杂任务的可靠交付能力，同时维持安全边界、可恢复性和 Token/服务器资源效率。** Agent 按这些权重分析测试失败、任务记录与用户反馈；外部趋势不能单独成为升级理由。

改进必须通过独立验证：原有测试不能回归，新增能力须有针对性回归测试。评估基线由用户控制，Agent 可以提出修改建议但不能在同一轮悄悄修改验收标准来证明自己成功。报告区分「已验证」「未验证」「推测」。

## 8. 接口草案

- `POST /api/upgrades`：创建升级任务；输入目标、预算、时限和授权档位，服务端校验权限并保存快照。
- `POST /api/tasks/{id}/pause`：请求安全暂停；只接受升级任务。
- `POST /api/tasks/{id}/resume`：按检查点恢复；校验授权仍有效、预算未超、基线未冲突。
- `POST /api/tasks/{id}/discard`：明确放弃并清理候选副本。
- `POST /api/tasks/{id}/authorize`：只批准某一项具体的越界请求，不可由 Agent 自行调用；保存批准人、范围和有效期。
- `GET /api/tasks/{id}`：返回任务类型、阶段、授权摘要、暂停状态、决策事件、来源和用量。
- 现有候选差异、退回修改和批准合入流程继续作为正式工作区唯一入口。

状态变更必须原子化。同一时刻最多运行一个升级任务，避免超出当前单 Worker 和服务器资源承载能力。

## 9. 实施顺序和验收门槛

1. **授权与状态**：添加升级类型、章程快照、阶段状态和安全暂停/继续接口；假模型测试，不消耗真实 API Token。
2. **持久化恢复**：阶段检查点、服务重启恢复、基线冲突保护、未知模型调用状态处理。
3. **Runner 协作停止**：操作 ID、进程组终止、临时目录清理；验证候选源文件仍保留。
4. **受限联网搜索与决策日志**：来源可追溯；恶意网页不能改变权限；Agent 的目标选择和理由能完整审计。
5. **授权内自主实施**：Agent 能在无用户逐步确认时选一项改进、实施、测试、迭代，并停在待验收候选；越界时安全进入 `waiting_owner`。
6. **隔离服务器验证**：独立项目名、端口和数据卷；先用假模型验证暂停/重启恢复，再由用户配置预算做受控 API 验证。不得覆盖仍待人工验收的线上任务。

发布门槛：用户不在线时，Agent 能完成授权内的一轮闭环；暂停或重启后可续跑；已完成步骤不重复执行；正式工作区哈希保持不变直到人工批准；预算触顶后停止新调用；越界动作会等待授权；原有任务测试全部通过。

## 10. 当前版本差距与不做事项

当前候选版本已有单 Worker、SQLite 任务/事件、隔离候选副本、无网络 Runner 和人工合入，但没有联网搜索、持久检查点或授权章程；现有停止是取消，不是可恢复暂停。V1 应增量复用这些部件，避免建立第二套并行任务系统。

本阶段不做：Agent 自我扩权或改预算；自动合并主分支、Push、生产部署；无预算循环；未经授权读取密钥；任意外网命令执行；自动删除或修改正式数据。

## 11. 参考模式

- LangGraph 持久化检查点 / interrupt-resume：参考阶段状态保存和恢复。
- GitHub Copilot Coding Agent 隔离环境与差异审阅：参考候选工作区和人工合入边界。
- Temporal 协作式取消 / heartbeat：参考长任务取消协作；当前轻量服务器不需要先引入 Temporal 服务。
